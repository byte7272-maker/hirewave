# Harbor Design System

The single visual language for the whole product, extracted from the two
**canonical dashboard stat cards** — *Matches* and *In pipeline*. Every other
surface composes from these tokens and components so nothing looks like it
belongs to a different product.

This is a **living document**. When a surface needs something new, extend the
system here instead of one-off styling a page.

---

## 1. Tokens

### Color — five role scales (StyleSystem)

All UI color flows through five semantic roles. Never hard-code hex/rgb/hsl, and
never add decorative color names (`brand`, `surface`, `muted`, …) to Tailwind.

| Role         | Meaning                                   | Anchor       |
| ------------ | ----------------------------------------- | ------------ |
| `background` | page canvas, cards, panels, quiet tints    | `background-50` |
| `primary`    | brand + conversion (**emerald**)           | `primary-500` |
| `accent`     | second theme (**coral**) — one clear moment| `accent-500` |
| `secondary`  | supporting actions, filters, metadata (**sand**) | `secondary-500` |
| `foreground` | text / strongest neutral contrast (**ink**) | `foreground-950` |

- **Ink** = `text-foreground-950` · **secondary text** = `text-foreground-700`
  · **muted text** = `text-foreground-500`.
- **Success / warn / danger** are expressed through the tone roles, not raw
  colors: emerald (`primary`) reads as success/quality, coral (`accent`) as
  warn/attention, sand (`secondary`) as neutral. (e.g. `fitTone()` in
  `src/pages/dashboard/components/tone.ts`.)
- Solid tone fills pair with a `background-50` label
  (`dark:text-foreground-950` in dark mode) to keep WCAG AA contrast.
- Tokens are CSS variables holding **OKLCH channel values** (e.g.
  `--primary-500: 0.560 0.140 158;`), bound in Tailwind as
  `oklch(var(--primary-500) / <alpha-value>)`. Dark mode remaps the same
  variables under `.dark`, so class names stay semantic.

### Shape & rhythm — card anatomy tokens

Defined in `src/index.css` and exposed to Tailwind via `borderRadius`.

| Token               | Value  | Tailwind         | Use                          |
| ------------------- | ------ | ---------------- | ---------------------------- |
| `--radius-card`     | 1rem   | `rounded-card`   | cards, panels, stat cards    |
| `--radius-tile`     | 0.75rem| `rounded-tile`   | icon tiles, small surfaces   |
| `--radius-control`  | 0.5rem | `rounded-control`| buttons, chips, controls     |
| `--card-padding`    | 1.25rem| `p-5`            | card interior padding        |
| `--tile-size`       | 2.75rem| (`.hw-tile`)     | the 44px square icon tile    |

> Pills/avatars use `rounded-full`. Cards use `rounded-2xl`/`rounded-card`,
> tiles `rounded-xl`/`rounded-tile`, controls `rounded-lg`/`rounded-md`.

### Elevation — border, never shadow

The canonical cards use a **hairline border** (`border-background-200`) and, on
interaction, a primary border + a transform lift (`.hw-lift`). **Shadows are not
part of the system** — they read as dirty. Depth comes from layered
`background` steps and borders.

### Typography

| Role      | Variable          | Face             | Use                     |
| --------- | ----------------- | ---------------- | ----------------------- |
| heading   | `--font-heading`  | Fraunces (serif) | titles, **metric numbers** |
| body      | `--font-body`     | Plus Jakarta Sans| body copy               |
| label     | `--font-label`    | Plus Jakarta Sans| buttons, labels, forms  |

Scale used by the canonical cards: **metric** `font-heading text-3xl md:text-4xl
font-medium leading-none text-foreground-950`; **section title**
`font-heading text-base font-medium`; **label** `text-sm font-medium
text-foreground-700`; **caption/muted** `text-xs text-foreground-500`.

### Motion

One budget, defined globally in `src/index.css`:

- Entrance: `.animate-rise` (content settling), `.animate-fade-in-up` (lists/blocks).
- Hover: `.hw-lift` = translate only (no shadow).
- Overlays: `.animate-pop` / `.animate-fade`; live dot `.hw-pulse`.
- All neutralized under `prefers-reduced-motion: reduce`.

| `ListRow`        | `ListRow.tsx`     | List unit. Optional quality `spine`, `leading`/`trailing` slots, `title`/`subtitle`/`meta`. |
| `Modal`          | `Modal.tsx`       | Dialog on `Card` + `Button`. `title`, `onClose`, optional `icon` + `size`. |

| `SelectField`    | `Field.tsx`       | Select sharing the field styling; `inline` label for toolbars. |

### Guardrails

- **Contrast:** text on tinted cards stays `foreground-950/700/500`; solid fills
  get a `background-50` (or dark `foreground-950`) label.
- **States:** every interactive element keeps hover / focus (`:focus-visible`
  ring in `primary-500`) / active / disabled (`opacity-60`, `not-allowed`).
- **Overlays:** every modal/dialog scrim is a mode-agnostic dark veil
  (`bg-foreground-950/45 dark:bg-black/55-60`). Never leave a scrim on
  `bg-foreground-950` alone — in dark mode `foreground-950` is near-white, so it
  becomes a light wash instead of a dim.
- **Photo backdrops:** a photographic header/hero scrim must be built from
  `black` (`from-black/90 via-black/65 to-black/35`), never `foreground-950`
  (which inverts to a near-white veil). Text and the icon tile over a photo use
  the dual label `text-background-50 dark:text-foreground-950` so they stay light
  in both schemes. See `PageHeader`.
- **Responsive:** cards reflow to a single column; the version strip scrolls.
- **Behavior is untouched** by visual work — these components are presentation only.

### Existing adapters

- `src/pages/dashboard/components/StatCard.tsx` → re-exports `base/StatCard`.
- `src/pages/dashboard/components/PanelHeader.tsx` → re-exports `base/SectionHeader`.
- `src/pages/dashboard/components/FitBandBar.tsx` → the **one** fit-band
  distribution visual (legend chips over a segmented bar). It backs the Matches
  `MatchQualityBar`, the Flagged `FlaggedQualityBar`, the Saved `SavedQualityBar`
  and the home *Top matches* summary; pass `interactive` + `onBandChange` to let
  a band chip / segment filter a list down to that band. When a band filter is
  active, the shared `BandFilterNotice` renders the "showing N of M" line + a
  one-click **Reset band** chip above the list (Matches + Flagged).
- `src/pages/dashboard/components/BandFilterNotice.tsx` → the companion readout
  for an active fit-band filter (shown / total + reset chip), so filtering a
  ranked list feels identical across Matches and Flagged.
- `src/pages/dashboard/documents/components/VersionCard.tsx` → one card in the
  **Versions marquee**: a lazily-fetched, template-rendered **mini-preview** of
  that saved version with a hover/focus zoom popover, plus a **changed-vs-current**
  badge (its own content signature vs the active version's). It pairs with
  `useVersionPreview` (fetch + parse + fingerprint) and the shared
  `StyleThumbnail` renderer; `useInView` (`src/hooks/useInView.ts`) gates the
  fetch to visible cards, and `parseResumeMarkdown` (`src/lib/resumeMarkdown.ts`)
  turns a version's stored markdown back into JSON Resume. `VersionsStrip` drives
  a **roving-tabindex** focus model over these cards (← / → / Home / End), so
  keyboard focus moves card to card and the preview follows. Trim and typography
  still flow through the five StyleSystem role scales and the `--font-*` variables.

A new `src/lib/previewSpotlight.ts` marks the matching heading inside the preview’s own iframe (matched by heading text — exact, then a tolerant “contains”, so a section the API names slightly differently still lands), animates a highlighted band over it, and clears the previous mark; `VersionHtmlPreview` gained opt-in `spotlightSection` / `spotlightNonce` props (re-applied on every iframe (re)load, so a `srcDoc` swap never drops the mark); `HighlightsDocumentViewer` threads them through and shows a **“Spotlighting the {section} section”** banner (with a Clear action) plus an accent ring around the preview; and the page holds the spotlight, scrolls the left column to it, and clears it when the résumé changes. On desktop the sticky viewer is already in view, so the scroll is a no-op; on mobile it brings the viewer up. (2) **The dead modal is deleted.** The in-editor “My Work Highlights” modal (`EvidenceImportPanel` — the old extract-facts wizard) was unreachable: every editor entry point already navigates to the `/dashboard/experience` workspace (`openEvidence`), and nothing ever opened the modal (`setEvidenceOpen(true)` was never called). It is removed, along with its `evidenceOpen` state, its hand-off `runEvidence` helper and the render block in both editor hosts (`ResumeTemplatesPanel`, `useStructuredImprove`) — so the workspace stays the one home for the tool.
